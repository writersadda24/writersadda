# Technical Writing Field Guide

Technical writing spans software, products, operations, regulated work, and organizational knowledge. This guide maps the discipline across **where it is used, what it produces, how teams work, which tools they choose, what skills support the work, and the business problems documentation can help address**.

It is a practical orientation, not a claim that one writer or studio has delivered every asset in every industry. The examples are representative, the tool landscape changes, and regulated or safety-critical work requires the right domain owners and review controls.

## How to use this guide

- **Planning a documentation project?** Start with the reader task and deliverable, then choose a workflow that fits your product and publishing constraints.
- **Choosing a platform?** Compare collaboration, review, reuse, publishing, accessibility, localization, and ownership needs before selecting a tool.
- **Assessing expertise?** Separate the breadth of technical communication as a field from a provider's verified project history and hands-on platform experience.
